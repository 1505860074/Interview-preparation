## Part 1. Bash 基础信息（面试地基）

### 1.1 先分清：终端 / Shell / Bash 是什么关系

初学者最容易混，先用大白话理清：

- **终端（Terminal）**：那个黑框框窗口本身，是"显示器 + 键盘"这层界面（在你机器上是 kitty）。它只负责显示字符、接收你敲的键，本身不"懂"命令。
- **Shell**：真正解释你命令的"翻译官"。你敲 `ls`，是 Shell 把它翻译成"去调用 `/bin/ls` 这个程序"。Shell 是一个程序。
- **Bash**：Shell 的一种具体实现，全称 **B**ourne **A**gain **SH**ell（"born again"双关，意为"重生的 Bourne shell"）。它是对老的 Bourne shell（`sh`）的增强重写。

> **面试一句话**："终端是界面，Shell 是命令解释器，Bash 是最主流的一种 Shell 实现。"

**Shell 家族要能报得出名（高频送分题）：**

| 名字 | 全称/来历 | 特点 |
|---|---|---|
| `sh` | Bourne Shell | 最古老的标准 Shell，现在常是 `dash` 的软链接（Debian/Ubuntu） |
| `bash` | Bourne Again Shell | Linux 默认，功能最全，本手册主角 |
| `dash` | Debian Almquist Shell | 极简、快，Ubuntu 里 `/bin/sh` 就指向它，只支持 POSIX 语法 |
| `zsh` | Z Shell | 交互体验强（补全/主题，oh-my-zsh），macOS 默认 |
| `fish` | Friendly Interactive Shell | 开箱即用友好，但语法不兼容 bash |

**为什么这个区别在面试重要？** 因为很多人写脚本用了 bash 独有语法（比如 `[[ ]]`、数组），却写 `#!/bin/sh`，在 Ubuntu 上 `/bin/sh` 是 dash，一跑就报错。能说清这点，说明你真的踩过坑。

### 1.2 脚本三要素：Shebang、执行权限、执行方式

**① Shebang（释伴/羊角符）—— 脚本第一行 `#!`**

```bash
#!/bin/bash
echo "hello"
```

- `#!` 后面跟"用哪个解释器来跑这个文件"。内核看到 `#!/bin/bash`，就用 `/bin/bash` 去执行剩下的内容。
- 名字来历：`#` 叫 **sh**arp（或 hash），`!` 叫 **bang**，合起来 **shebang**。
- **更可移植的写法**：`#!/usr/bin/env bash`。因为 bash 不一定在 `/bin/bash`（有些系统在 `/usr/local/bin`），`env` 会去 `PATH` 里找 bash，更通用。
- **常见坑**：Shebang 必须是文件**第一行第一列**，前面不能有空行或空格，否则失效。

**② 执行权限**

```bash
chmod +x script.sh   # 给文件加上"可执行"权限
```

不加权限直接 `./script.sh` 会报 `Permission denied`。

**③ 三种执行方式（区别是高频考点）**

```bash
bash script.sh     # ①用一个新的 bash 子进程跑，不需要执行权限，不看 shebang
./script.sh        # ②按 shebang 指定的解释器跑，需要执行权限
source script.sh   # ③在【当前】shell 里跑，不开子进程
. script.sh        # ③的简写，. 就是 source
```

**核心区别：`source`（`.`）不开子进程，会影响当前 shell。**

- `bash script.sh` / `./script.sh`：都会**新开一个子 shell**。脚本里 `cd /tmp` 或 `export X=1`，跑完回到你终端，目录没变、`X` 也没有——因为改的是子进程的环境，子进程一结束就没了。
- `source script.sh`：在**当前 shell** 里逐行执行，脚本里的 `cd`、变量、函数定义**会保留**。这就是为什么改完 `~/.bashrc` 要 `source ~/.bashrc` 才生效——你要让改动作用在当前这个 shell 上。

> **经典面试题**："脚本里 `cd` 到某目录，为什么执行完终端还在原地？" → 因为它在子 shell 里 `cd`，子 shell 退出后不影响父 shell。想生效就 `source`。

### 1.3 变量：定义、引用、作用域

**定义与引用：**

```bash
name="Alice"      # 定义。注意：等号两边【不能有空格】！
echo "$name"      # 引用要加 $
echo "${name}"    # 更规范：加花括号界定边界
```

- **等号两边不能有空格**是初学者头号错误。`name = "Alice"` 会被理解成"执行 `name` 命令，参数是 `=` 和 `"Alice"`"，报 `command not found`。
- **为什么推荐 `${name}`**：花括号明确变量名边界。比如想拼接 `${name}_backup`，如果写 `$name_backup`，bash 会去找名叫 `name_backup` 的变量（找不到，返回空）。

**环境变量 vs 普通变量（作用域）：**

```bash
X=1            # 普通变量：只在当前 shell 可见，子进程看不到
export Y=2     # 环境变量：会传递给子进程
```

- 用 `export` 导出后，你启动的子程序（比如另一个脚本、python 进程）才能通过环境读到它。这就是为什么 `PATH`、`HOME` 这些要 `export`。
- **`local`（函数内局部变量）**：在函数里用 `local var=...`，变量只在函数内有效，不污染全局。写健壮脚本必备。

```bash
myfunc() {
  local tmp="only inside"   # 出了函数就消失
  echo "$tmp"
}
```

> **面试点**：能主动提"我在函数里用 `local` 避免变量泄漏到全局"，是工程素养的体现。

### 1.4 引号：单引号 / 双引号 / 反引号 / 不加引号（**极高频，务必吃透**）

这是 Bash 面试**最爱考**的地方，因为它直接关系脚本健不健壮。

| 写法 | 变量 `$var` 会展开吗 | 命令替换 `$(...)` 会执行吗 | 通配符 `*` 会展开吗 |
|---|---|---|---|
| `'单引号'` | ❌ 不展开，原样 | ❌ 不执行 | ❌ 不展开 |
| `"双引号"` | ✅ 展开 | ✅ 执行 | ❌ 不展开 |
| 不加引号 | ✅ 展开 | ✅ 执行 | ✅ 展开（危险！） |

```bash
name="world"
echo '$name'     # 输出：$name        （单引号：所见即所得）
echo "$name"     # 输出：world        （双引号：变量展开）
echo $name       # 输出：world        （但下面这种情况会出事↓）
```

**为什么"几乎永远给变量加双引号"是铁律？** 看这个经典事故：

```bash
file="my file.txt"     # 文件名带空格
rm $file               # ❌ 展开成：rm my file.txt  → 被当成删两个文件 my 和 file.txt
rm "$file"             # ✅ 展开成：rm "my file.txt" → 正确删一个文件
```

不加引号时，bash 会对结果做 **单词拆分（word splitting）**（按空格/制表符/换行拆成多个词）和 **通配符展开（globbing）**。文件名里有空格、`*`、`?` 时就会闯祸。

> **面试铁律**："引用变量时默认加双引号 `"$var"`，除非我明确需要拆分或通配。" 这一句能说出来，面试官立刻知道你写过靠谱脚本。你的 `backup.sh` 里处理路径、`webm2mp4-watch.sh` 里处理文件名，都必须靠它。

**反引号 `` `cmd` `` vs `$(cmd)`（命令替换）：** 两者都是"把命令的输出替换到这里"，但：

```bash
today=`date +%F`      # 老写法，反引号
today=$(date +%F)     # 新写法，推荐
```

推荐 `$(...)`，原因：① 可读性好；② **可嵌套**。反引号嵌套要层层转义反斜杠，`$()` 直接套：

```bash
echo "$(dirname "$(readlink -f "$0")")"   # 一层套一层，清晰
```

### 1.5 特殊变量（面试常直接点名问）

| 变量 | 含义 |
|---|---|
| `$0` | 脚本自己的名字（路径） |
| `$1 $2 …` | 第 1、2… 个位置参数（命令行传进来的参数） |
| `$#` | 参数的**个数** |
| `$@` | **所有参数**（数组式，`"$@"` 每个参数独立保留） |
| `$*` | 所有参数（`"$*"` 会拼成一个字符串） |
| `$?` | **上一条命令的退出码**（0=成功，非0=失败）——错误处理核心 |
| `$$` | 当前脚本的**进程号 PID**（常用来生成唯一临时文件名） |
| `$!` | 最后一个**后台**进程的 PID |
| `$_` | 上一条命令的最后一个参数 |

**`"$@"` vs `"$*"` 是压轴级考点**，单独讲（见 1.5.1）。

#### 1.5.1 `$@` 与 `$*` 到底差在哪

- **不加引号时**：`$@` 和 `$*` 表现几乎一样，都会被拆分。
- **加引号时（关键）**：
  - `"$@"` → 展开成 `"$1" "$2" "$3"`，**每个参数是独立的一项**，原样保留（含空格）。
  - `"$*"` → 展开成 `"$1c$2c$3"`，把所有参数用 `IFS` 的第一个字符（默认空格）**拼成一个字符串**。

```bash
# 假设脚本收到 3 个参数：  a   "b c"   d
for x in "$@"; do echo "[$x]"; done
# 输出（正确，3 项）：
# [a]
# [b c]
# [d]

for x in "$*"; do echo "[$x]"; done
# 输出（错误地并成 1 项）：
# [a b c d]
```

> **结论 / 面试答案**："遍历、转发参数一律用 `"$@"`，它能正确保留每个参数的边界（尤其带空格的）。`"$*"` 只适合把所有参数拼成一整句字符串输出。" 这题答对，Bash 印象分直接拉满。

### 1.6 参数扩展（Parameter Expansion）—— Bash "字符串处理"的看家本领

这是进阶脚本里出现频率极高、但初学者最不熟的部分。掌握它，很多任务不用调用 `sed`/`awk` 就能搞定，脚本更快更干净。

**默认值 / 兜底系列：**

```bash
${var:-default}   # var 为空/未定义 → 用 default（不改变 var）
${var:=default}   # var 为空/未定义 → 用 default，并【赋值】给 var
${var:?msg}       # var 为空/未定义 → 打印 msg 到 stderr 并【退出脚本】（做参数校验）
${var:+value}     # var 有值 → 用 value，否则空（反向逻辑）
```

真实用法（你的脚本里就适合）：

```bash
INTERVAL="${INTERVAL:-5}"          # 允许外部覆盖，否则默认 5 秒（webm2mp4 场景）
RETENTION_DAYS="${RETENTION_DAYS:-7}"
: "${BACKUP_DIR:?必须设置 BACKUP_DIR 环境变量}"   # 没设就直接报错退出（backup 场景）
```

**长度 / 子串：**

```bash
${#var}           # 字符串长度
${var:2}          # 从第 2 个字符（0 起）到末尾
${var:2:3}        # 从第 2 个字符起，取 3 个
```

**掐头去尾（提取路径 / 扩展名，超常用）：**

```bash
path="/home/xyz/Videos/rec.webm"
${path##*/}       # 去掉最长的 "*/"  → rec.webm     （取文件名，等价 basename）
${path%/*}        # 去掉最短的 "/*"  → /home/xyz/Videos （取目录，等价 dirname）
${path##*.}       # → webm            （取扩展名）
${path%.*}        # → /home/xyz/Videos/rec （去掉扩展名）
```

记忆法：**`#` 在键盘 `3` 上、靠左 → 从左边（开头）删；`%` 靠右 → 从右边（结尾）删。单个是"最短匹配"，双写是"最长匹配"。**

真实用法（webm2mp4 的核心一步）：

```bash
f="rec.webm"
mp4="${f%.webm}.mp4"     # 把 .webm 换成 .mp4 → rec.mp4
```

**查找替换：**

```bash
${var/old/new}    # 替换【第一个】old
${var//old/new}   # 替换【所有】old
${var^^}          # 全转大写（bash 4+）
${var,,}          # 全转小写
```

> **面试加分**：当被问"怎么把 `a.webm` 变成 `a.mp4`"，很多人张口就是 `sed`；你答 `"${f%.webm}.mp4"`——纯内建、不起子进程、更快——立刻显得内行。

### 1.7 数组（你的 `backup.sh` 采集软件清单会用到）

**索引数组：**

```bash
arr=(apt conda pip npm)      # 定义
echo "${arr[0]}"             # 取第一个 → apt
echo "${arr[@]}"             # 所有元素（推荐加引号 "${arr[@]}" 保留边界）
echo "${#arr[@]}"            # 元素个数 → 4
arr+=(vscode)                # 追加一个元素
for pm in "${arr[@]}"; do    # 遍历（一定加引号！）
  echo "处理 $pm"
done
```

- **关键坑**：遍历数组必须 `"${arr[@]}"`（带引号带 `@`）。写成 `${arr[*]}` 或不加引号，带空格的元素会被拆散。

**关联数组（字典 / 哈希，bash 4+，做去重和计数神器）：**

```bash
declare -A count             # 必须先 declare -A 声明
count[error]=3
count[warn]=5
echo "${count[error]}"       # → 3
for key in "${!count[@]}"; do        # ${!count[@]} 取所有【键】
  echo "$key => ${count[$key]}"
done
```

> **面试项目结合点**：`backup.sh` 采集 apt/conda/pip/npm/扩展 多类清单，天然适合"数组存包管理器列表 + 循环导出"。能说出"我用数组统一管理要采集的包管理器，循环里 `"${pm[@]}"` 逐个导出清单"，就把项目和语法点绑上了。

### 1.8 算术运算

```bash
a=3; b=4
echo $((a + b))       # 7   —— $(( )) 算术展开，最常用
echo $((a > b ? a : b))   # 支持三元
(( a++ ))             # (( )) 算术命令，可自增
let "c = a * b"       # let 也能算，但不如 $(( )) 直观
```

- **注意**：`$(( ))` 里的变量**不用加 `$`**（`$((a+b))` 而非 `$(($a+$b))`，两者都行但前者更简洁）。
- **Bash 原生不支持浮点**！`$((3/2))` 得 `1`（整数除法）。要小数得靠 `bc` 或 `awk`：`echo "scale=2; 3/2" | bc` → `1.50`。这也是常考陷阱。

### 1.9 条件测试：`test` / `[ ]` / `[[ ]]` / `(( ))` 的区别（高频）

四种"判断真假"的写法，区别要讲清：

```bash
[ "$a" = "$b" ]        # 传统 test，[ 其实是个命令，等价 test "$a" = "$b"
[[ "$a" == "$b" ]]     # bash 增强版，更安全更强大（推荐）
(( a > b ))            # 算术判断，专门比数字
```

**`[ ]`（POSIX test）：**
- `[` 本质是一个**命令**（就是 `/usr/bin/[`），所以 `[` 后、`]` 前**必须有空格**，`["$a"]` 会报错。
- 里面变量**必须加引号**，否则变量为空时语法会崩：`[ $x = 1 ]` 当 `$x` 为空 → `[ = 1 ]` 报错。
- 逻辑用 `-a`（与）`-o`（或），比较易错。

**`[[ ]]`（bash 关键字，推荐）：**
- 是 bash 的**关键字**不是命令，解析更智能：变量不加引号一般也不崩（但仍建议加）。
- 支持 `&&` `||`、支持 `==` 通配匹配、支持 `=~` 正则：

```bash
[[ "$file" == *.webm ]]        # 通配：以 .webm 结尾？
[[ "$s" =~ ^[0-9]+$ ]]         # 正则：全是数字？
[[ -f "$path" && -r "$path" ]] # 文件存在且可读
```

**常用测试运算符（要背熟）：**

| 判断 | 写法 |
|---|---|
| 字符串相等 / 不等 | `=` / `!=`（`[[ ]]` 里也可 `==`） |
| 字符串为空 / 非空 | `-z "$s"` / `-n "$s"` |
| 数字比较 | `-eq -ne -gt -lt -ge -le`（equal/not/greater/less than…） |
| 文件存在 | `-e path` |
| 是普通文件 / 目录 | `-f path` / `-d path` |
| 可读 / 可写 / 可执行 | `-r` / `-w` / `-x` |
| 文件 A 比 B 新 | `A -nt B`（newer than） |

> **面试答法**："我默认用 `[[ ]]`，因为它是 bash 关键字，对空变量和特殊字符更安全，还支持 `=~` 正则和 `&&`。只有要写 POSIX sh 兼容脚本时才退回 `[ ]`。" 顺便：**数字比较别用 `>`**，在 `[ ]` 里 `>` 是重定向！要用 `-gt`，或在 `(( ))` 里用 `>`。

### 1.10 流程控制

**if / elif / else：**

```bash
if [[ "$count" -gt 10 ]]; then
  echo "多"
elif [[ "$count" -gt 0 ]]; then
  echo "少"
else
  echo "空"
fi
```

- `then` 可以另起一行，也可以像上面用 `;` 接在同一行。`fi` 是 `if` 倒写表示结束（bash 的"幽默"：`if`→`fi`，`case`→`esac`）。

**case（多分支，比一堆 elif 清爽）：**

```bash
case "$ext" in
  webm)        echo "视频，需要转码" ;;
  mp4|mkv)     echo "已是常见格式" ;;    # | 表示"或"
  *.log)       echo "日志" ;;            # 支持通配
  *)           echo "其他" ;;           # * 是兜底（相当于 default）
esac
```

- 每个分支用 `;;` 结束，别忘了。`*)` 做兜底。

**for 的三种形态：**

```bash
for f in *.webm; do echo "$f"; done          # ①遍历 glob/列表（最常用）
for i in {1..5}; do echo "$i"; done          # ②遍历序列（花括号展开）
for (( i=0; i<5; i++ )); do echo "$i"; done  # ③C 风格
```

**while / until：**

```bash
while true; do              # 死循环（守护脚本核心，见 webm2mp4）
  do_work
  sleep 5
done

until ping -c1 host; do sleep 1; done   # until：条件为假时循环，直到成立
```

**遍历文件的正确姿势（**极重要**，Part 2 会深挖）：**

```bash
while IFS= read -r line; do
  echo "$line"
done < file.txt
```

### 1.11 函数

```bash
greet() {           # 定义（也可写 function greet { ... }）
  local who="$1"    # 用 $1 取参数，和脚本参数一样
  echo "Hello, $who"
  return 0          # 返回【退出码】0-255，不是返回值！
}

greet "world"       # 调用：直接写函数名 空格 参数，不要加括号
result=$(greet "world")   # 想拿"返回值"要靠 echo + 命令替换捕获
```

**关键认知（面试常挖）：**
- 函数的 `return` 只能返回 **0–255 的退出码**（表示成功/失败），**不能返回字符串或大数字**。
- 想"返回数据"，标准做法是 **`echo` 出来，调用方用 `$(...)` 捕获**（上面 `result=$(...)`）。
- 函数参数就是 `$1 $2 $@`，和脚本级参数用法一致；`$0` 仍是脚本名不是函数名。

### 1.12 输入输出：`echo` / `printf` / `read`

```bash
echo "简单输出"
echo -n "不换行"
printf "%s = %d\n" "count" 42     # 格式化，比 echo 可控（跨平台更稳）
read -r name                       # 从标准输入读一行到 name（-r 防止反斜杠被转义）
read -rp "请输入名字: " name       # -p 带提示
```

- **面试小坑**：`echo -e`（解释转义）、`echo -n`（不换行）在不同系统/shell 行为不一致，**要稳就用 `printf`**。
- `read` 永远加 `-r`，否则输入里的 `\` 会被吃掉。

### 1.13 重定向与管道（Bash 的灵魂）

**三个标准流（要能报出编号）：**

- `0` = stdin（标准输入）
- `1` = stdout（标准输出）
- `2` = stderr（标准错误）

**重定向：**

```bash
cmd > out.txt      # stdout 覆盖写入文件（等价 1>）
cmd >> out.txt     # stdout 追加
cmd 2> err.txt     # stderr 写入文件
cmd > out 2>&1     # stdout 和 stderr 都进 out（2>&1：把 2 指向 1 现在的去处）
cmd &> out         # bash 简写：stdout+stderr 都进 out
cmd 2>/dev/null    # 丢弃错误输出（/dev/null 是"黑洞"）
cmd < in.txt       # 从文件喂给 stdin
```

**`2>&1` 顺序陷阱（经典考点）：**

```bash
cmd > out 2>&1     # ✅ 对：先把 1 指向 out，再让 2 也指向"1 现在的去处"=out
cmd 2>&1 > out     # ❌ 错：先让 2 指向 1（此时 1 还是终端），再把 1 改到 out
                   #    结果 stderr 还留在终端，只有 stdout 进了文件
```

> 记法：`2>&1` 是"把 stderr 复制到 stdout **当前**的方向"，所以**必须放在 `> out` 之后**。这题几乎是重定向的招牌题。

**管道 `|`：** 把左边命令的 stdout 接到右边命令的 stdin：

```bash
cat log | grep error | wc -l     # 找 error 行并计数
apt list --installed | wc -l     # 你 backup.sh 采集清单的雏形
```

**Here-Document（生成多行文本 / 配置文件，很实用）：**

```bash
cat > config.ini <<EOF
[server]
host=$HOST        # 变量会展开
port=8080
EOF

cat > config.ini <<'EOF'   # 引号包住 EOF → 里面变量【不】展开，原样输出
port=$PORT
EOF
```

**Here-String（喂一个字符串给 stdin）：**

```bash
grep error <<< "$logline"
```

### 1.14 命令连接：`;` `&&` `||` `&`

```bash
a ; b       # 顺序执行，不管 a 成败都执行 b
a && b      # a 成功（退出码0）才执行 b   —— "与"
a || b      # a 失败（非0）才执行 b       —— "或"
a &         # a 放后台运行，立刻返回执行下一条
```

真实惯用法：

```bash
mkdir -p "$dir" && cd "$dir"          # 建目录成功才进去
command -v ffmpeg >/dev/null || { echo "缺 ffmpeg"; exit 1; }   # 没装就报错退出
```

> `command -v xxx` 用来"检测某命令是否存在"，比 `which` 更可移植，是脚本里做依赖检查的标准姿势——你的 `deploy.sh`/`webm2mp4` 检查 ffmpeg 就该这么写。

### 1.15 退出码（Exit Code）与错误处理入门

- 每条命令跑完都有一个 **0–255 的退出码**：`0 = 成功`，`非 0 = 失败`（不同数字代表不同错误）。
- 用 `$?` 取上一条命令的退出码：

```bash
grep error log.txt
if [[ $? -ne 0 ]]; then echo "没找到 error"; fi
```

- 脚本用 `exit N` 主动返回退出码，`N` 就是给调用者（另一个脚本 / CI 系统）看的成败信号。
- **为什么重要**：CI/CD、`&&` 链、systemd 判断服务是否崩溃，全靠退出码。写脚本要"该失败就返回非 0"，别永远 `exit 0` 骗上游。

这引出 Part 2 的重头戏：**`set -euo pipefail` 严格模式** 和 **`trap`**——把"错误处理"从"能跑"升级到"健壮"，也是面试区分度最高的地方。

### 2.1 严格模式 `set -euo pipefail`（**进阶第一课，必背**）

几乎所有"专业"的 bash 脚本开头都会有这一行。它把 bash 默认"过于宽容"的行为改严格，能提前暴露 bug。

```bash
#!/usr/bin/env bash
set -euo pipefail
```

逐个拆解（面试可能让你解释每一个字母）：

- **`set -e`（errexit）**：任何命令返回非 0（失败）就**立即退出脚本**。默认情况下 bash 会"错了也接着往下跑"，很危险——比如 `cd /backup` 失败了还继续 `rm -rf *`，就删错地方了。`-e` 让脚本"一错就停"。
- **`set -u`（nounset）**：用到**未定义的变量**就报错退出。防止变量名打错、或忘了赋值导致 `rm -rf "$DIR/"` 里 `$DIR` 为空 → 变成 `rm -rf /`。
- **`set -o pipefail`**：管道里**任意一环**失败，整条管道就算失败。默认管道的退出码只看**最后一个**命令，`false | true` 会被当成成功——`pipefail` 修正这点。
- 常见还会加 **`set -x`**（xtrace）：把每条实际执行的命令打印出来，调试神器（生产环境去掉）。

**为什么面试爱考？** 因为它体现你**默认就在意健壮性**。能说清"`-e` 一错即停、`-u` 防未定义变量、`pipefail` 让管道失败不被吞掉"，直接甩开一大票只会 `echo` 的候选人。

**⚠️ `set -e` 的坑（能讲出来是高手）：**

- `set -e` 遇到你**故意允许失败**的命令会误伤。比如 `grep pattern file`（没匹配到会返回 1），在 `-e` 下会直接让脚本退出。解决：给它兜底 `grep pattern file || true`。
- `set -u` 下访问可能不存在的变量要用 `"${var:-}"` 给个默认空值，否则直接报错。

> **项目结合**：你的 `backup.sh`/`deploy.sh` 做的是"采集清单、删旧文件、部署还原"这类**有副作用**的操作，正是最该用 `set -euo pipefail` 的场景——一步失败就停，绝不能"错着往下删"。面试可以说："备份/部署脚本我一定开严格模式，因为它们有破坏性副作用，宁可早停也不能带病执行。"

### 2.2 `trap`：信号处理与"退出时清理"（守护脚本 & 临时文件必备）

`trap` 让你"捕获某个信号或事件，触发时执行一段代码"。两大用途：

**用途① 退出时自动清理（最常用）：**

```bash
tmpfile=$(mktemp)                       # 创建临时文件
trap 'rm -f "$tmpfile"' EXIT            # 无论脚本怎么结束，都删掉临时文件
# ... 中间用 $tmpfile 干活 ...
# 脚本结束（正常/报错/被 Ctrl-C）时，trap 都会触发，临时文件不残留
```

- `EXIT` 是"脚本退出"这个伪信号，**不管正常退出还是中途出错都会触发**，所以是做清理的最佳挂载点。
- 好处：不用在每个 `exit` 前都手写一遍 `rm`，一处 `trap` 管全局。

**用途② 优雅响应 Ctrl-C / 终止信号（守护进程）：**

```bash
running=true
trap 'echo "收到停止信号，收尾中..."; running=false' INT TERM

while $running; do
  do_work
  sleep 5
done
echo "已干净退出"
```

**常见信号（面试可能点名）：**

| 信号 | 编号 | 触发 | 能否被捕获 |
|---|---|---|---|
| `SIGINT` | 2 | 你按 Ctrl-C | ✅ 能 |
| `SIGTERM` | 15 | `kill PID` 默认发的、systemd 停服务发的 | ✅ 能（**优雅关闭**就靠它） |
| `SIGKILL` | 9 | `kill -9` | ❌ **不能捕获**，强杀 |
| `SIGHUP` | 1 | 终端关闭 | ✅ 能 |

> **项目结合**：`webm2mp4-watch.sh` 是 `while true` 守护循环，又被 systemd 管理。systemd `stop` 时默认发 `SIGTERM`。你可以说："守护脚本我会 `trap ... TERM` 做优雅退出——比如正在 ffmpeg 转码时收到停止信号，先让当前这个转完/或标记好状态再退，避免留下半个损坏的 mp4。" 这就把 `trap` 和你的项目、和"数据完整性"绑在一起了，非常出彩。
>
> 顺带一个高手细节：`SIGKILL`（`kill -9`）**无法被 trap**，所以"能被 -9 也不留烂摊子"要靠别的设计（如原子写入、临时文件 + `mv`），不能只靠 trap。

### 2.3 子 shell `( )` vs 命令组 `{ }`（作用域考点）

```bash
( cd /tmp; do_something )      # 子 shell：cd 只在括号内生效，出来目录不变
{ cd /tmp; do_something; }     # 命令组：在【当前】shell 执行，cd 会影响后续
```

- **`( )` 开一个子进程**：里面的 `cd`、变量修改都是"沙盒"，不影响外面。适合"我想临时进某个目录干点事，干完自动回来"。
- **`{ }` 不开子进程**：只是把几条命令组成一组（常用于给一组命令统一重定向，或配合 `||`）。注意语法：`{` 后要空格，最后一条命令要有 `;`。

真实用法：

```bash
# 一组命令统一写日志
{ echo "开始"; do_work; echo "结束"; } >> run.log 2>&1

# 依赖检查失败就报错退出（{} 把两句绑一起）
command -v ffmpeg >/dev/null || { echo "缺 ffmpeg" >&2; exit 1; }
```

> **面试点**："想临时切目录又不污染当前 shell，就用 `( cd dir && ...)` 子 shell。" 你 `backup.sh` 里若要进各个目录打包，用子 shell 最干净。

### 2.4 逐行读文件的"黄金写法"（初学者 99% 会踩坑）

**❌ 常见错误：`for line in $(cat file)`**

```bash
for line in $(cat file.txt); do echo "$line"; done   # 错！
```

问题：`$(cat file)` 的结果会被**单词拆分**——它是按空格/换行都拆，所以一行里有空格就被拆成多个，还会触发通配符展开。**它不是"逐行"，是"逐词"。**

**✅ 正确写法：`while IFS= read -r`**

```bash
while IFS= read -r line; do
  echo "处理：$line"
done < file.txt
```

三个细节，每个都要能解释（**高频追问**）：

- **`IFS=`**：`IFS`（Internal Field Separator，内部字段分隔符）临时设为空，**防止行首行尾的空格/制表符被 `read` 吃掉**，保证整行原样。
- **`read -r`**：`-r` 让反斜杠 `\` 当普通字符，不被当转义。**永远加 `-r`**。
- **`< file.txt`**：把文件重定向给循环的 stdin，让 `read` 一次读一行。

> **面试满分答法**：被问"怎么逐行读文件"，你先说正确写法 `while IFS= read -r line; do ...; done < file`，再主动补一句"不能用 `for line in $(cat file)`，那是按分隔符拆词不是拆行，遇到空格就散了"。主动点出反例 = 真的踩过坑。

**遍历"文件名列表"更稳的写法（含特殊字符/空格）：** 用 `find ... -print0` + `read -d ''`：

```bash
find ~/Videos -name '*.webm' -print0 | while IFS= read -r -d '' f; do
  echo "转码：$f"
done
```

`-print0` 用 `\0`（空字符）分隔文件名，`read -d ''` 按 `\0` 读——因为文件名里唯一不可能出现的字符就是 `\0`，这样连带换行的变态文件名也能安全处理。

### 2.5 `find` + `xargs`：批量处理与"保留期清理"

你的 `webm2mp4-watch.sh` 有一步"清理超过 7 天的视频"，这正是 `find -mtime` 的典型场景：

```bash
find ~/Videos -type f -mtime +7 -delete          # 删除 7 天前修改的普通文件
find ~/Videos -name '*.webm' -mmin +1 -print     # 找出 1 分钟前就没再动的 webm（判稳雏形）
```

要点：
- `-mtime +7`：修改时间在 **7×24 小时之前**（`+` 是"更早于"，`-7` 是"最近 7 天内"，`7` 是"正好第 7 天那一天"）。这个 `+/-` 语义是考点。
- `-mmin` 按分钟；`-type f` 只要普通文件（排除目录）；`-name '*.webm'` 按名字过滤（注意通配符要**加引号**，否则被 shell 先展开了）。
- `-delete` 是 find 内建删除，比 `-exec rm` 稍安全（但仍要先用 `-print` 预览确认再删）。

**`xargs`（把上一步输出变成下一步命令的参数）：**

```bash
find . -name '*.log' -print0 | xargs -0 rm -f            # 批量删，-0 配 -print0 处理空格
find . -name '*.webm' -print0 | xargs -0 -I{} ffmpeg -i {} {}.mp4   # -I{} 占位
```

- `-0` / `-print0` 搭配处理带空格文件名（同 2.4 逻辑）。
- `-I{}` 把每个输入替换到 `{}` 位置，一条条执行。

> **面试项目结合**：讲 webm2mp4 的清理逻辑时，主动说"保留期清理我用 `find -mtime +$RETENTION_DAYS -delete`，`$RETENTION_DAYS` 用 `${RETENTION_DAYS:-7}` 允许外部覆盖"，一句话串起 find 时间判断 + 参数扩展默认值两个知识点。

### 2.6 守护循环：`while true; do ...; sleep; done` vs cron vs systemd

这是你 webm2mp4 项目的**核心设计决策**，也是很好的面试素材。

**朴素守护循环：**

```bash
while true; do
  scan_and_convert
  sleep "${INTERVAL:-5}"    # 每 5 秒扫一次
done
```

**三种"定时/常驻"方案对比（面试很爱让你比较）：**

| 方案 | 粒度 | 崩溃自动重启 | 开机自启 | 适用 |
|---|---|---|---|---|
| `while+sleep` 脚本 | 任意秒级 | ❌ 需自己保活 | ❌ | 简单常驻，但脚本挂了就没了 |
| `cron` | **最小 1 分钟** | 每次是新进程 | ✅ | 周期性批处理（如每日备份） |
| `systemd` 服务 | 任意（配 timer 也行） | ✅ `Restart=on-failure` | ✅ `enable` | 需秒级 + 保活 + 开机自启的常驻服务 |

> **你项目里现成的高质量回答**：`webm2mp4-watch.sh` 要 **5 秒粒度**，而 cron 最小只有 1 分钟，所以你选了 systemd 用户服务，还能拿到"崩溃自动重启 + 开机自启"。而 `backup.sh` 是"偶尔手动跑一次"的批处理，就没必要常驻，将来要定时的话 cron 就够。**能讲出"为什么这个用 systemd、那个用 cron/手动"，就是架构判断力**，比单纯背语法值钱得多。

**判稳的意义（数据完整性思维）：** 录屏还在写入时文件大小在涨，这时候转码会得到半个坏文件。所以要"等文件连续几秒大小不变（录完稳定）再转"。这体现你考虑了**并发/竞态**，是很打动人的细节。

### 2.7 原子操作与幂等性（备份/归档类脚本的灵魂）

**幂等（Idempotent）**：同一个脚本**跑一次和跑多次结果一样**，不会重复干活或搞坏状态。你的归档系统"增量归档"、备份系统"重复跑不出乱子"都依赖它。

常见幂等手法：

```bash
mkdir -p "$dir"                 # -p：已存在也不报错（幂等建目录）
ln -sf target link             # -f：已存在就覆盖（幂等建软链）
cp -n src dst                  # -n：目标已存在就不覆盖（避免重复处理）
[[ -f "$done_flag" ]] && exit 0   # 用"标记文件"记录已完成，跑过就跳过
```

**原子写入（避免半成品文件）：** 直接写目标文件，如果中途崩了会留下损坏的半个文件。正确做法是**先写临时文件，成功后再 `mv` 覆盖**——`mv` 在同一文件系统内是**原子**的（要么完全成功要么完全没动）：

```bash
tmp=$(mktemp)
generate_data > "$tmp" && mv "$tmp" "$final.json"   # 成功才替换，读者永远看到完整文件
```

> **项目结合**：
> - 归档系统"增量 + INDEX.md"：可以讲"我用文件是否已归档做幂等判断，Stop Hook 每次触发只处理新增会话，重复触发不会重复归档"。
> - webm2mp4：ffmpeg 转码若直接写 `final.mp4`，中途被 kill 会留坏文件；更稳是写临时名再 `mv`，保证下游看到的永远是完整 mp4。这正好呼应 2.2 里"SIGKILL 无法 trap，要靠原子写兜底"。

### 2.8 安全：注入、危险的 `rm`、敏感文件排除

你的 `system-backup` 明确做了"**彻底排除 `.ssh/.aws/token` 等敏感文件**"，这是绝佳的安全话题素材。

**① 变量一定加引号（防注入/防误删，见 1.4）**：`rm -rf "$dir"` 而不是 `rm -rf $dir`；`$dir` 若为空或带空格会酿大祸。

**② `set -u` + 默认值防"空变量删根目录"：**

```bash
rm -rf "${BACKUP_DIR:?BACKUP_DIR 未设置}"/*   # 变量为空直接报错退出，绝不会变成 rm -rf /*
```

**③ 敏感文件排除（你的项目核心安全策略）**：两道防线——

- `.gitignore` 排除 `.ssh/ .aws/ *token*` 等，**从版本控制层面**杜绝；
- 脚本内维护一个 **SENSITIVE 黑名单数组**，采集时主动跳过：

```bash
SENSITIVE=(".ssh" ".aws" ".gnupg" "*token*" "*.pem" "*credential*")
# 采集 dotfiles 时跳过黑名单
```

> **面试答法（很加分）**："备份脚本最大的风险是把密钥、token 一起打包上传到 git。我做了双保险：`.gitignore` 层面排除，脚本内再维护一个敏感文件黑名单主动跳过；真正的密钥我走移动硬盘手动拷，绝不进仓库。" —— 这展示**安全意识 + 防御性设计**，是资深味道很浓的回答。

**④ `eval` 和不受信输入**：`eval "$user_input"` 会把用户输入当代码执行，是注入重灾区，能不用就不用。面试被问"bash 有什么安全隐患"，可答"`eval`、未加引号的变量、拼接命令字符串，都可能命令注入"。

### 2.9 调试与质量：`set -x`、`bash -n`、`shellcheck`

面试问"你怎么调试 bash 脚本"，标准三件套：


## Part 4. 面试题库 A —— 理论问答题（通用 · 带详解）

> 用法：先盖住答案自己口述，再对照。每题结构：**Q 问题 → A 参考答案（能背的精简版）→ 💡 讲解 → ⚠️ 陷阱/加分点**。标 ⭐ 的是高频必会。

### A 组：基础概念

**⭐ A1. Shell、Bash、终端有什么区别？**
- **A**：终端是显示/输入的界面；Shell 是解释命令的程序（命令解释器）；Bash 是 Shell 的一种主流实现（Bourne Again Shell）。
- 💡 关系是"界面 → 解释器 → 具体实现"三层。
- ⚠️ 加分：能补一句"`sh` 在 Ubuntu 上常指向 `dash`，所以用了 bash 特有语法（数组、`[[ ]]`）却写 `#!/bin/sh` 会报错"。

**A2. `#!/bin/bash` 这一行叫什么？作用是什么？**
- **A**：叫 Shebang，指定用哪个解释器执行本脚本。
- 💡 内核读到 `#!` 后按指定路径调用解释器。
- ⚠️ 必须是第一行第一列；更可移植写 `#!/usr/bin/env bash`（去 PATH 找 bash）。

**⭐ A3. `bash script.sh`、`./script.sh`、`source script.sh` 三者区别？**
- **A**：前两个都开**子 shell** 执行（`./` 需要执行权限、看 shebang）；`source`（`.`）在**当前 shell** 执行，会保留脚本里的 `cd`、变量、函数。
- 💡 所以改完 `.bashrc` 要 `source` 才生效。
- ⚠️ 经典追问："脚本里 cd 了，为什么终端目录没变？"→ 子 shell 里 cd，退出即失效。

### B 组：变量与引号（高频重灾区）

**⭐ B1. 单引号、双引号、不加引号的区别？**
- **A**：单引号原样输出（变量/命令/通配都不展开）；双引号会展开变量和命令替换、但不做单词拆分和通配；不加引号会额外做**单词拆分 + 通配符展开**（危险）。
- ⚠️ 铁律：**引用变量默认加双引号 `"$var"`**。

**⭐ B2. 为什么要给变量加双引号？举个不加会出事的例子。**
- **A**：不加引号时 bash 会对变量值做单词拆分和通配。若 `file="a b.txt"`，`rm $file` 会删 `a` 和 `b.txt` 两个文件；`rm "$file"` 才正确。
- 💡 文件名带空格、`*`、`?` 时尤其致命。

**B3. `$(cmd)` 和反引号 `` `cmd` `` 有何区别？**
- **A**：都是命令替换（把输出嵌入）。推荐 `$()`：可读性好、**可嵌套**；反引号嵌套要层层转义。

**B4. 普通变量和 `export` 的环境变量有什么区别？**
- **A**：普通变量只在当前 shell 可见；`export` 后成为环境变量，会传给子进程。
- ⚠️ 加分：函数里用 `local` 声明局部变量，避免污染全局。

### C 组：参数与特殊变量

**⭐ C1. `$@` 和 `$*` 的区别？**
- **A**：不加引号时几乎一样。**加引号是关键**：`"$@"` 展开为独立的 `"$1" "$2" ...`，每个参数边界保留；`"$*"` 把所有参数用 IFS 首字符拼成**一个**字符串。
- 💡 遍历/转发参数一律用 `"$@"`。

**C2. `$?`、`$$`、`$!`、`$#` 分别是什么？**
- **A**：`$?` 上条命令退出码；`$$` 当前进程 PID；`$!` 最近一个后台进程 PID；`$#` 参数个数。

**C3. `${var:-default}` 和 `${var:=default}` 区别？**
- **A**：都是"var 为空则用 default"，但 `:=` 会**顺便把 default 赋值给 var**，`:-` 不改变 var。
- ⚠️ `${var:?msg}` 则是为空就报错退出，用于必填参数校验。

**C4. 怎么取路径的文件名和目录名（不调用 basename/dirname）？**
- **A**：`${path##*/}` 取文件名，`${path%/*}` 取目录；`${f%.*}` 去扩展名，`${f##*.}` 取扩展名。
- 💡 `#` 从左删、`%` 从右删；双写是最长匹配。

### D 组：测试与流程控制

**⭐ D1. `[ ]`、`[[ ]]`、`(( ))` 有什么区别？**
- **A**：`[ ]` 是 POSIX test 命令（要注意空格、变量要加引号）；`[[ ]]` 是 bash 关键字，更安全、支持 `&&`/`==`通配/`=~`正则；`(( ))` 专做算术比较。
- 💡 默认用 `[[ ]]`；写 POSIX sh 才退回 `[ ]`。

**D2. 在 `[ ]` 里比较数字大小为什么不能用 `>`？**
- **A**：`[ ]` 里 `>` 会被当成**重定向**，会创建文件。数字比较要用 `-gt -lt -ge -le -eq -ne`；或在 `(( ))` 里用 `>`。

**D3. `-z` 和 `-n` 是什么？**
- **A**：`-z "$s"` 判断字符串为空，`-n "$s"` 判断非空。

**D4. `for` 循环有哪几种写法？**
- **A**：遍历列表/glob `for f in *.txt`；遍历序列 `for i in {1..5}`；C 风格 `for ((i=0;i<5;i++))`。

### E 组：重定向与管道（招牌考点）

**⭐ E1. `0`、`1`、`2` 分别代表什么？**
- **A**：0=stdin 标准输入，1=stdout 标准输出，2=stderr 标准错误。

**⭐ E2. `cmd > out 2>&1` 和 `cmd 2>&1 > out` 有什么不同？**
- **A**：前者 stdout 和 stderr 都进 out；后者只有 stdout 进 out、stderr 仍留在终端。
- 💡 `2>&1` 是"让 2 指向 1 **当前**的方向"，所以必须放在 `> out` **之后**才能把 stderr 也导进文件。

**E3. 怎么丢弃一个命令的所有输出？**
- **A**：`cmd > /dev/null 2>&1`（或 bash 简写 `cmd &>/dev/null`）。`/dev/null` 是黑洞设备。

**E4. `|` 管道传递的是什么？stderr 会被管道传吗？**
- **A**：管道把左边的 **stdout** 接到右边的 stdin；**stderr 默认不走管道**。要把 stderr 也送进管道：`cmd 2>&1 | next`。

**E5. Here-Document 是什么？`<<EOF` 和 `<<'EOF'` 区别？**
- **A**：Here-Doc 用于向命令喂多行文本。`<<EOF` 内部变量/命令会展开；`<<'EOF'`（引号包住定界符）则原样输出、不展开。

### F 组：错误处理与健壮性（区分度最高）

**⭐ F1. `set -e`、`set -u`、`set -o pipefail` 各是什么？**
- **A**：`-e` 命令失败即退出；`-u` 用未定义变量即报错；`pipefail` 管道任一环失败则整条失败（默认只看最后一个）。
- ⚠️ 加分：`-e` 会误伤"允许失败"的命令（如 `grep` 没匹配返回 1），要 `|| true` 兜底。

**F2. 退出码 0 和非 0 代表什么？为什么重要？**
- **A**：0=成功，非0=失败。`&&`/`||`、CI/CD、systemd 判断服务成败都靠它，所以脚本"该失败就返回非0"。

**⭐ F3. `trap` 是干什么的？举一个用途。**
- **A**：捕获信号或退出事件并执行代码。最常见是 `trap 'rm -f "$tmp"' EXIT` 做退出清理（正常/报错/Ctrl-C 都会触发），或 `trap ... TERM` 做守护进程优雅退出。

**F4. `SIGTERM`、`SIGINT`、`SIGKILL` 有什么区别？哪个不能捕获？**
- **A**：SIGINT(2)=Ctrl-C；SIGTERM(15)=默认 kill / systemd stop，用于优雅关闭；SIGKILL(9)=强杀，**无法被 trap 捕获**。
- ⚠️ 加分：因为 -9 杀不住，"不留半成品"要靠原子写（临时文件 + `mv`）而非只靠 trap。

**F5. `command -v xxx` 有什么用？为什么比 `which` 好？**
- **A**：检测某命令是否存在（做依赖检查）。`command -v` 是 shell 内建、更可移植，`which` 是外部命令、行为因系统而异。

### G 组：进程 / 作业 / 实用

**G1. `&`、`nohup`、`disown` 分别做什么？**
- **A**：`cmd &` 放后台；`nohup cmd &` 让它忽略挂断信号、终端关了也不死；`disown` 把已在后台的作业从当前 shell 的作业表移除，避免退出时被带走。

**G2. `while true; do ...; sleep; done`、cron、systemd 三种常驻/定时方案怎么选？**
- **A**：`while+sleep` 简单但脚本挂了就没了、不能开机自启；cron 适合周期批处理但**最小 1 分钟**粒度；systemd 服务能做**秒级 + 崩溃重启 + 开机自启**，常驻服务首选。

**G3. 逐行读文件的正确写法？为什么不用 `for line in $(cat f)`？**
- **A**：用 `while IFS= read -r line; do ...; done < f`。`for line in $(cat f)` 是**按分隔符拆词不是拆行**，一行里有空格会被拆散，还触发通配。
- 💡 `IFS=` 防首尾空格被吃，`-r` 防反斜杠转义。

**G4. Bash 能做浮点运算吗？**
- **A**：`$(( ))` 只做**整数**运算（`3/2=1`）。浮点要靠 `bc`（`echo "scale=2;3/2"|bc`）或 `awk`。

**G5. 你平时怎么保证 bash 脚本质量 / 怎么调试？**
- **A**：`bash -n` 查语法、`bash -x`/`set -x` 跟踪执行、`shellcheck` 静态检查揪常见错误、变量默认加引号、开 `set -euo pipefail`。
- 💡 这题是"软素质"送分题，把工程习惯一次性倒出来。

**G6. `>` 和 `>>` 区别？**
- **A**：`>` 覆盖写（文件先清空），`>>` 追加写。

**G7. glob 通配符和正则表达式一样吗？**
- **A**：不一样。文件名通配（glob）里 `*` = 任意多个字符、`?` = 单个字符、`[abc]` = 字符集；正则里 `*` 是"前一个字符重复 0+ 次"，语义完全不同。`[[ str == pattern ]]` 用 glob，`[[ str =~ regex ]]` 才是正则。

## Part 5. 面试题库 B —— 项目追问题（结合你的项目 · 模拟深挖）

> 面试官听你讲完项目后，会顺着追问细节，验证"是不是真做的、想得深不深"。下面模拟这种深挖，每题给**追问 + 参考回答思路**。建议你把回答改成自己的话讲熟。
> ⚠️ 因为我没读你的真实源码（按你要求），下面的"做法"是**基于项目描述的合理推断**。你回答前请对照自己脚本的真实实现微调，别把没做过的说成做了。

### B-1 追问 `system-backup`（backup.sh / deploy.sh）

**Q1. 你这个备份脚本，最担心出什么问题？怎么防的？**
> 思路：抓住"**误删**"和"**泄密**"两大风险。① 泄密：`.ssh`/`.aws`/token 绝不能进 git —— 我做了 `.gitignore` + 脚本内敏感文件黑名单双保险，真密钥走移动硬盘手拷。② 误删/误还原：脚本开 `set -euo pipefail`，删除/还原路径用 `"${VAR:?}"` 防空变量，绝不出现 `rm -rf` 拼到空变量变成删根目录的情况。

**Q2. 为什么开头要 `set -euo pipefail`？不加会怎样？**
> 思路：备份/部署有破坏性副作用，必须"一步失败立刻停"。不加 `-e`，某步失败（比如 `cd` 到不存在的目录）还会继续往下执行后面的删除/覆盖，可能在错误的位置操作；`-u` 防我变量名打错导致空值；`pipefail` 防"导出清单 | 处理"这种管道里前一环失败被后一环的成功掩盖。

**Q3. 你用什么数据结构管理"要采集哪些包管理器"和"要排除哪些敏感文件"？**
> 思路：都用 **bash 数组**。一个数组列 apt/conda/pip/npm/… 各包管理器，循环里逐个跑对应的导出命令；另一个 `SENSITIVE=()` 数组列敏感路径/通配，采集 dotfiles 时跳过。遍历时用 `"${arr[@]}"` 保留每项边界。好处：加一个包管理器/一条排除规则只改数组，不动逻辑。

**Q4. `deploy.sh` 在新机器上一键还原，怎么保证"重复跑不出问题"（幂等）？**
> 思路：还原操作尽量幂等——`mkdir -p` 建目录、软链用 `ln -sf` 覆盖、包安装本身"已装则跳过"。这样部署到一半失败，重跑也不会重复报错或搞坏已还原的部分。

**Q5. 如果让你把这个备份做成"每天自动跑"，你会怎么加？**
> 思路：它是周期性批处理、不需要秒级，所以用 **cron**（`crontab -e` 加一行每天凌晨跑 `backup.sh` 并把输出重定向到日志），而不是 systemd 常驻。顺带可以在脚本里加"成功后打个时间戳标记 / 失败时发个通知"。—— 这里能对比出你懂 cron 和 systemd 的适用边界。

**Q6.（安全深挖）万一敏感文件不小心已经被 commit 进 git 了怎么办？**
> 思路：坦诚这是真实风险。`.gitignore` 只能挡"还没被跟踪的"，已入库的要用 `git rm --cached` 从索引移除并提交，历史里的还得用 `git filter-repo`/BFG 清理，且**认为该密钥已泄露要轮换**。这体现你知道"gitignore ≠ 删历史"。

### B-2 追问 录屏→mp4 闭环（webm2mp4-watch.sh）

**Q1. 为什么用 systemd 服务，而不是直接把脚本丢后台、或者用 cron？**
> 思路（这是这个项目最亮的点）：我需要**5 秒粒度**扫描，而 **cron 最小只有 1 分钟**，满足不了；直接 `nohup &` 丢后台又没有"崩溃自动重启 + 开机自启"。systemd 用户服务一次性解决三件事：秒级常驻、`Restart=on-failure` 崩溃拉起、`enable` 开机自启。所以是"需求决定选型"。

**Q2. 录屏文件还在写入时你就去转码，会得到半个坏文件吧？你怎么处理的？**
> 思路（竞态/数据完整性，非常加分）：对，所以我加了**判稳**——只有当一个 webm 的大小（或修改时间）**连续若干秒不再变化**、判定录制已结束，才交给 ffmpeg。相当于用"稳定一段时间"来近似"文件已写完"，避免转到写了一半的文件。

**Q3. 如果转码转到一半，服务被 `kill -9` 或断电了，会不会留下一个损坏的 mp4？怎么避免？**
> 思路（把 trap 的局限讲透，秒变高手）：`SIGKILL`（-9）**无法被 trap 捕获**，所以光靠信号处理兜不住。更稳的做法是**原子写**：ffmpeg 先输出到临时文件名，转码成功后再 `mv` 成最终 `.mp4`（同分区 `mv` 是原子的）。这样下游看到的 `.mp4` 要么不存在、要么是完整的，永远不会是半成品；下次扫描发现原 webm 还在、临时文件是垃圾，清掉重转即可。

**Q4. 转完就删原 webm，万一转码其实失败了呢？会不会把原文件也弄丢？**
> 思路：删原文件前必须**确认转码成功**——检查 ffmpeg 的**退出码**（`$?` 为 0）且产物文件存在且大小合理，才 `rm` 原 webm；否则保留 webm 并记日志。绝不能"转了就删"。

**Q5. `${INTERVAL:-5}`、`${RETENTION_DAYS:-7}` 这种写法是什么意思？为什么这么写？**
> 思路：参数扩展的默认值语法——外部设了环境变量就用外部的，没设就用默认（5 秒 / 7 天）。好处是**可配置**：改行为不用改代码，`RETENTION_DAYS=14 ./webm2mp4-watch.sh` 就能临时改保留期。

**Q6. 保留期清理那段具体怎么写的？**
> 思路：`find ~/Videos -type f -mtime +"$RETENTION_DAYS" -delete` —— `-mtime +N` 匹配"修改时间在 N×24 小时之前"的文件，`-type f` 只删普通文件。上线前我会先用 `-print` 而不是 `-delete` 跑一遍确认删的对不对，再换成 `-delete`。

**Q7. 这个 while true 死循环会不会很吃 CPU？**
> 思路：不会，因为循环体每轮末尾 `sleep 5` 让出 CPU，绝大部分时间进程在睡眠，只有醒来那一下扫一次目录。关键是**别写没有 sleep 的忙等**（busy-wait），那才会把一个核跑满。

### B-3 通用项目追问（任何项目都可能被问）

**Q1. 你写 bash 脚本一般怎么保证质量？**
> 思路：开 `set -euo pipefail`、变量默认加引号、`command -v` 做依赖检查、写完过 `shellcheck`、关键路径先 `bash -n` 查语法 / `bash -x` 跟踪。

**Q2. 你什么时候选择用 bash，什么时候换 Python？**
> 思路（很好的价值观题）：**流程编排、调用系统命令、文件/进程操作、粘合工具链**——bash 最顺手、最短。一旦涉及**复杂数据结构、字符串解析、需要单元测试、逻辑超过一两百行**，我就转 Python，更可读可维护。我的项目也是这么分的：备份/转码这种"调系统命令+文件操作"的用 bash，归档解析、数据转换这种"处理结构化数据"的用 Python。

**Q3. 你的脚本给别人用，怎么让它更好用/更健壮？**
> 思路：参数用 `${VAR:-默认}` 可配置、必填项 `${VAR:?}` 校验、缺依赖 `command -v` 提前报错并给提示、关键步骤打日志、`set -e` 出错即停并返回有意义的退出码、开头写用途注释。

## Part 6. 速查表 Cheat Sheet

> 临场前 5 分钟扫这一页。

**特殊变量**
```
$0 脚本名   $1.. 参数   $# 参数个数   "$@" 各参数独立   "$*" 拼成一串
$? 上条退出码   $$ 当前PID   $! 后台PID   $_ 上条最后参数
```

**参数扩展**
```
${v:-def}  空则用def          ${v:=def}  空则用def并赋值
${v:?msg}  空则报错退出        ${v:+val}  有值才用val
${#v}      长度                ${v:2:3}   子串(第2起3个)
${v#x} ${v##x}  从左删最短/最长   ${v%x} ${v%%x}  从右删最短/最长
${v/a/b}   替换首个            ${v//a/b}  替换全部
${path##*/} 取文件名           ${path%/*} 取目录        ${f%.*} 去扩展名
```

**测试**
```
[[ -e f ]]存在  -f普通文件  -d目录  -r可读 -w可写 -x可执行
[[ -z "$s" ]]空  -n非空      A -nt B  A比B新
数字: -eq -ne -gt -lt -ge -le      [[ ]]里: == 通配   =~ 正则   && ||
```

**重定向**
```
> 覆盖   >> 追加   2> 错误   &> 全部   2>/dev/null 丢错误
cmd > out 2>&1   (顺序不能反)      <<EOF here-doc      <<< here-string
```

**连接**
```
a ; b  顺序   a && b  a成功才b   a || b  a失败才b   a &  后台
command -v x >/dev/null || { echo 缺x; exit 1; }   # 依赖检查模板
```

**健壮性/调试**
```
set -euo pipefail        # 严格模式(脚本开头)
trap 'rm -f "$tmp"' EXIT # 退出清理
bash -n f   # 查语法    bash -x f / set -x   # 跟踪    shellcheck f   # 静态检查
```

**逐行读文件（黄金写法）**
```bash
while IFS= read -r line; do
  echo "$line"
done < file.txt
```

**守护循环骨架**
```bash
#!/usr/bin/env bash
set -euo pipefail
INTERVAL="${INTERVAL:-5}"
trap 'echo bye; exit 0' TERM INT
while true; do
  do_work
  sleep "$INTERVAL"
done
```

**常用一行流**
```bash
today=$(date +%F)                         # 2026-08-28
mp4="${f%.webm}.mp4"                      # 换扩展名(纯内建)
find dir -type f -mtime +7 -delete        # 删7天前文件
grep -c error log || true                 # 计数且不被 set -e 误杀
tmp=$(mktemp) && cmd > "$tmp" && mv "$tmp" out   # 原子写
```

## Part 7. 面试临场建议（把"辅助技能"讲成加分项）

**1. 摆正定位，别硬装专家。**
对后端/测试/AI 工程岗，Bash 是"能把活自动化起来"的**工程习惯证明**，不是主考点。你的目标是让面试官觉得"这人写脚本很靠谱、能独立把工具链搭起来"，而不是"这人是 shell 底层专家"。所以重点展示**健壮性、安全、自动化思维**，而不是冷门语法。

**2. 主动亮"工程素养关键词"。**
被问到 bash，哪怕问题很简单，也顺势带出这几个词，印象分立刻不一样：
> "我一般开 `set -euo pipefail`、变量默认加引号、依赖用 `command -v` 检查、写完过 `shellcheck`。"
这一句话胜过背十个语法点，因为它证明你**默认就在意质量**。

**3. 把项目讲成一条主线（复述这句）。**
> "我用 Bash 主要做**自动化和工具链粘合**——把重复的手工操作（备份、录屏转码、环境部署）固化成**健壮、幂等、可重复**的脚本，再用 hook / systemd / cron 让它们自动跑。"
然后用 `system-backup` 和 `webm2mp4` 两个例子落地。有主线、有例子，比零散答题有力得多。

**4. 准备好"深挖三连"的亮点。** 面试官爱往深里问，提前备好这三个"越问越显水平"的点：
- **webm2mp4 判稳** → 你考虑了**竞态/数据完整性**（不转写了一半的文件）。
- **SIGKILL 不能 trap → 原子写兜底** → 你懂**信号的边界**和**原子操作**。

这三个点任何一个讲清楚，都能让"辅助技能"变成记忆点。

**5. 不会就诚实 + 展示方法论。**
遇到真不会的（比如某冷门参数），别硬编。可以说："这个具体参数我记不准，但我会 `man` 一下 / 用 `shellcheck` 兜底 / 先在小样本上 `bash -x` 验证再上生产。"——**展示解决问题的方法比假装全会更值钱**，尤其面对经验丰富的面试官。

**6. 讲项目只讲真做过的。**
主力放 `system-backup`、`webm2mp4`（真·bash 主导、细节答得上）；归档 hook、飞书同步点到"用脚本/cron 做自动化调度"即可；"start 启动器"只是设计稿、没落地，别当成品讲。**被追问答不上比不提更减分。**

**7. 临场结构：一句定义 → 一个例子 → 一个坑。**
回答任何 bash 知识点都可套这个三段式，显得有条理又有深度。例：问引号 →"双引号会展开变量但不拆词（定义）→ 比如 `rm "$file"` 处理带空格文件名（例子）→ 不加引号 `rm $file` 会把 `a b.txt` 删成两个文件（坑）。"

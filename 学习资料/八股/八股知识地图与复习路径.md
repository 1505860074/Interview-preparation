# 八股知识地图与复习路径（总索引）

> 目标：面向 **Coding Agent 岗 + 传统后端/基础架构岗** 双线投递，把"传统八股"从"面试前 0.5 天草草过一遍"提到"体系化长期建设"。
> 定位：这是 `学习资料/` 体系里**传统八股部分的入口文件**。先读本文，再按需进入各分册。
> 配套：Agent/RAG/大模型底层 属于"AI 理论八股"，在 `学习资料/Agent/`、`学习资料/RAG/`、`学习资料/大模型/`，本文只给它们的位置和依赖关系。

## 〇、先纠正一个危险的错觉

很多 Agent 岗的刷题清单会把"传统八股"压缩成 0.5 天、只留 OS/网络/DB 三条。这个压缩通常建立在一个**未经检验的假设**上：

> "Coding Agent 岗是纯应用岗，面试官只关心 Agent 实操，传统基础不重要。"

这个假设有三个破口：

1. **笔试/机考环节真实存在**。大厂（尤其 Moonshot、字节、阿里）普遍有笔试或线上机考，传统八股直接决定你能不能进下一轮。清单里没写笔试，不代表笔试不考。
2. **面试官会用你最弱的地方做快速定级**。你简历上的强信号是 C++ 实时控制 / 测试 / Agent 工程。面试官要在 30 分钟内判断"这人基础扎不扎实"，最省力的方法就是问**你简历上没写的**那部分——传统八股。你的简历越偏 Agent，他越会往传统基础上问，因为 Agent 方向的候选人太多、区分度低。
3. **传统后端/基础架构岗是同一批八股**。你说"我都在看"，那么第 2 层八股就是**两条投递线共用的公共资产**，边际收益比 AI 理论更高（AI 理论只对 Agent 线有用，传统八股两条线都用）。

**结论**：把传统八股从"0.5 天"提到"与 AI 理论并重的长期建设"，是双线投递下 ROI 最高的投入。理由不是"八股更重要"，而是"八股覆盖的岗位面更宽，且是你简历画像的补强项"。

**依赖关系（谁是谁的地基）**：

- L1（语言）→ L2（八股）：会写不等于懂原理。"为什么 Python 有 GIL" 属于 L1，"为什么线程切换要保存寄存器上下文" 属于 L2。**面试官问八股时，答案永远要能落回 L1 的具体代码**。
- L2a OS → L2b 网络：`send` 系统调用 → 协议栈 → 网卡，是同一条链路。讲 TCP 为什么要三次握手，先讲清两个 socket 之间的内核缓冲区。
- L2c 数据库 → L3 RAG：向量库也是数据库，B+树索引和 IVF/HNSW 索引是同一类问题的不同解法。**讲 RAG 检索时能顺口提"这本质是 ANN 检索，和 B+树索引是 trade-off 的两端"，是巨大加分**。
- L2d 系统设计 → L4 Agent：Agent 系统本质是一个"高失败率、需要重试/幂等/降级"的分布式系统。**Context 压缩、工具调用重试、死循环熔断，用的全是 L2d 的词汇**。这也是你从测试背景切 Agent 最有说服力的角度。

## 二、优先级矩阵：按「岗位相关性 × 你的缺口」排序

不按"教科书章节顺序"排，按"面试概率 × 你答不上的代价"排。P0 必会，P1 尽量会，P2 知道就行。

| 优先级 | 主题 | 相关岗位 | 你的缺口 | 你的现成钩子（★=可直接引用） |
|---|---|---|---|---|
| **P0** | 进程/线程/协程 + 死锁 | 后端/Agent/测试开发 | 大 | ★C++ 多线程伺服控制、systemd service、journalctl 排 crash |
| **P0** | TCP 三次握手/四次挥手 + 粘包 | 后端/Agent | 中 | ★自研 TCP 协议（5051 发 8000B 帧 / 5052 控制口）、struct packing |
| **P0** | 内存管理/虚拟内存/内存泄漏 | 后端/嵌入式/测试 | 中 | ★显存泄露专项测试、Xenomai 实时内存、编译期开关省内存 |
| **P0** | 事务 ACID + 隔离级别 + MVCC | 后端 | 中 | ★SQLite + FTS5 四套知识库、消息库事务一致性 |
| **P0** | RAG 全链路 | Agent | 低（有底子） | ★四套本地知识库跨源检索、CRG 最小上下文 |

| **P1** | B+树索引 + 索引失效场景 | 后端 | 中 | ★SQLite B-tree、FTS5 倒排 vs 向量检索 |

## 三、推荐节奏（无明确面试时间，按"周"为单位滚动）

不要试图一次学完。按下面的循环走，每轮 4–6 周，一轮结束后自测再进下一轮。

### 第 1 轮（P0 突击，4 周）—— 目标是把"最容易被问倒"的点清掉
| 周 | 主线 | 产出物（自测用） |
|---|---|---|
| W1 | L2a OS 上半：进程/线程/调度/死锁/虚拟内存 | 能不看资料画出「进程地址空间结构图」+ 讲清 4 个死锁条件各给一个真实规避手段 |
| W2 | L2a OS 下半：IO 五模型 + 文件系统 + 内存泄漏定位 | 能讲清 select/poll/epoll 差异 + 画出内存泄漏定位流程（RSS/top/ps/heaptrack 思路） |
| W3 | L2b 网络：TCP 状态机 + HTTP 各版本 + TLS | 能手画 TCP 三次握手四步图（含 SYN/ACK/seq/ack 具体值）+ 解释为什么 TIME_WAIT 等 2MSL |
| W4 | L2c 数据库：B+树/事务/隔离/MVCC + 索引失效 | 能手画 B+树并解释为什么非叶节点只存索引（减少 IO）+ 默写四种隔离级别的脏读验证 |

### 第 2 轮（P1 加厚 + L3 补齐，5 周）
| 周 | 主线 |
|---|---|
| W5 | L2c 深化：连接池/分库分表浅尝/慢查询 + 缓存四问题 |
| W6 | L2d 系统设计：缓存/MQ/幂等/限流/降级 |
| W7 | L3 RAG 全链路（**用你四套知识库项目当唯一贯穿案例**） |
| W8 | L3 大模型底层：注意力 → RoPE → KV Cache → 推理两阶段 |
| W9 | L4 Agent 应用：Loop/Context/MCP/Memory/Eval/安全 |
| W10 | 算法集中冲刺（每天 4–5 题，见 `学习资料/算法/`） |

### 第 3 轮及以后（滚动）
- 每次真实面试后，把答不上的题**回填**到对应分册的"我的弱区"清单，优先级提到 P0。
- 每 4–6 周重跑一次自测（见 §五），只测 P0+P1。
- 大模型底层按 `学习资料/大模型底层长期学习路线图.md` 的节奏走（这是系统性长线，不受面试周期影响）。

## 五、怎么自测"真的学会了"（别用"读过了"当掌握）

**错误标准**：读了一遍 feels 懂了。**这是最常见的自欺**。
**正确标准**：**在三个约束下能讲出来** —— ① 不看资料；② 能扛追问两层（"为什么"→"那如果…会怎样"）；③ 能落到一个具体场景/代码。

每个 P0 主题过这四关：
1. **默写关**：合上资料，在纸上默写结构图/流程图/状态机（TCP 状态机、B+树、进程地址空间、死锁四条件）。
2. **口述关**：对着手机录 2 分钟口述，卡壳就回看。
3. **追问题**：每个知识点自己先想 2 个"那如果…会怎样"。例：进程 vs 线程 → 追问"那 Go 的 goroutine 算线程吗"→ 追问"协程切换一定比线程切换快吗（不一定，涉及用户态/内核态、栈大小）"。
4. **迁移关**：能把这个知识点**挂到你做过的事**上（见每分册的"项目挂钩"小节）。**这一步是拿分的关键，也是本手册和你网上抄的八股文最大的区别。**

**推荐练法**：每个 P0 主题录一段 2–3 分钟口述视频/音频自测。这会暴露你"以为懂"的地方，效率远高于重读。

## 六、面试话术：怎么把"补八股"讲成加分项

如果面试官问"你最近在补什么"或"你的知识储备"，别说"我在刷八股"（掉价）。这样说：

> "我的工作横跨 C++ 实时控制、测试和 AI 工程三块，所以我有意识在补中间的**底层共通层**——操作系统、网络、数据库。这不是为了背八股，是因为我做 Agent 的时候踩过这些坑：知识库 SQLite 写入要处理事务一致性、上位机 TCP 通信要自己处理粘包、token 压缩本质是缓存和内存管理。理解这层之后，我设计 Context 压缩策略和工具重试机制时，判断会更准。"

**逻辑**：八股不是终点，是"你为什么能把 Agent 做对"的解释。把复习动机讲成"为工程问题找原理支撑"，而不是"为面试背书"。
